    How it works

    1. A lead arrives. StreetEasy emails the referral agent's alias. It lands in the shared referral inbox, and a Gmail filter there forwards anything from streeteasy.com to a Make mailhook. The inbox copy stays unread.
    2. Make passes it on. The scenario StreetEasy Referral Lead → Auto-Accept posts the email to the service on Railway within a few seconds.
    3. The service sorts it. A lead email is matched to an agent by the address it was sent to. A sign-in code email is held for a login that's waiting on it. Anything else is ignored. Leads past their deadline are skipped.
    4. It opens the agent's account. Each agent has a saved StreetEasy session on Railway's disk, so most leads need no login. When one is needed: Log in, email, shared password, then StreetEasy's verification switched from text to email, with the code read from the same inbox. "Remember this device" is ticked, so it lasts 30 days.
    5. It responds. On the agent's Connections list it finds the lead's card by building number and unit, clicks Respond Now, sends the pre-filled message, reloads, and checks the card no longer asks for a response.
    6. It reports. Done: an email to the tools inbox only. Anything a person must do: an ACTION NEEDED by <time> email to Derek with the property, the agent account and the link, plus a screenshot. Observe mode counts as needing a person, since it never clicks.

    Where each piece lives

    The service
    Railway, project casablanca. Code in the GitHub repo se-autoaccept; a push to main redeploys it. Its disk at /data holds the agent list, saved sessions, the run log and screenshots (kept 14 days).
    Make
    StreetEasy Referral Lead → Auto-Accept (inbox to service) and StreetEasy Lead Alerts → Email (service to Derek and the tools inbox).
    Shared inbox
    The referral inbox (named in the doc): the Gmail filter on from:streeteasy.com that forwards to Make. Its "forward all mail" setting goes elsewhere and isn't part of this.
    Settings
    Railway variables: the shared key, the StreetEasy password, the alert webhook, the service's own URL. Netlify variables for this page: SE_AUTOMATION_URL and SE_AUTOMATION_SECRET.
    Full notes
    docs/lead-accept/README.md in the Studio repo, and the se-autoaccept README.

    Routine and troubleshooting

    What needs a person, and when
    • Every week: the Make connection that sends alerts from creative@ expires. A scheduled reminder fires Tuesdays at 3:21 PM: Make → Connections → Creative Google Restricted connection → Reauthorize, then check StreetEasy Lead Alerts → Email is on. Until it's done, alerts queue up in Make and nobody is told.
    • Observe mode (the switch above): opens each lead and reports which button it would click, but doesn't click. Use it after StreetEasy changes its pages, or while a fix is going in. It takes effect on the next lead.
    • An agent with a different password: on their card below, Set own password. It's saved on the service, never shown again, and the next login uses it. The shared password changed: update it in Railway's variables; agents marked rejected are tried again.
    • "No agent match": the lead email didn't name an agent the service could find. The alert shows who it was sent to.
    • "Failed" on the Respond step: StreetEasy may have changed the button or the message pop-up. Switch to observe mode and send the run's screenshots to a Claude session.
    • Bot check: the service never tries to get past one. That lead goes to Derek.
